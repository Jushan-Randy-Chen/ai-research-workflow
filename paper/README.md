# paper/: the manuscript (an Overleaf project, synced with plain git)

`paper/` holds a separate git checkout of the Overleaf project. This research repo ignores everything in `paper/`
except this README, so the paper keeps its own history on Overleaf and collaborators keep editing in the browser.

## Setup (once)
1. Overleaf: create the project from the venue template (ICML, NeurIPS, ICLR, ...). Menu > Git integration gives the
   clone URL `https://git.overleaf.com/<project-id>` and a token.
2. Store the token outside the repo (never in a URL or a file in this repo):
   `git config --global credential.https://git.overleaf.com.helper "store --file=$HOME/.config/overleaf/credentials"`
   then the first clone asks for username `git` and the token.
3. `scripts/overleaf.sh clone <project-id>`
4. Set `"manuscript": "paper"` in `docs/research_loop/registry.json` (the default).

No Overleaf git access? Use Overleaf's GitHub sync with a private repo, or keep the LaTeX here and drop the
`paper/*` ignore rule. The gates only need the .tex files and the included figures on disk.

## Daily use
- `scripts/overleaf.sh pull` before every edit (Overleaf collaborators may have changed the text).
- Figures and tables are generated by `scripts/`, reviewed (`research-loop record-visual <name> --file <file>`), then
  copied to `paper/figures/` or `paper/tables/`.
- `scripts/overleaf.sh push "message"` refuses to push changed figures/tables while gate 4 is closed.
- Text-only edits (wording, related work, typos) are not gated.

## Conventions
- `figures/` only generated files (PDF, embedded fonts); `tables/` generated `.tex` snippets; `sections/*.tex`.
- Each figure/table caption states n (seeds/instances), what the band/interval is, and the budget.
- Bibliography: `references/refs.bib` in this repo is the master copy; copy it into the paper when it changes.
